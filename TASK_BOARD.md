## 1. Module List

### Wave 1 (Foundation)

**M01: Project Scaffolding & Configuration**
- **Tier:** T1
- **Effort:** S (<2hrs)
- **Source:** PROJECT_STRUCTURE.md, TECH_STACK.md
- **Scope:** Initializes the repository, configures the build system (pyproject.toml), sets up logging, and handles YAML configuration loading. Does not implement business logic.
- **Files Owned:** `pyproject.toml`, `requirements.txt`, `requirements-dev.txt`, `.env.example`, `config/default.yaml`, `src/anomaly_detection/__init__.py`, `src/anomaly_detection/common/logging.py`, `src/anomaly_detection/common/config.py`, `src/anomaly_detection/common/exceptions.py`.
- **Input:** None.
- **Output:** Installable Python package and config dict.
- **Acceptance Criteria:** `pip install -e .` succeeds; `config.py` loads `default.yaml` into a typed dictionary without errors.
- **Dependencies:** None.
- **Critical Path:** Yes

**M02: Core Data Contracts & Validators**
- **Tier:** T1
- **Effort:** M (2-4hrs)
- **Source:** DATA_SCHEMA.md
- **Scope:** Translates all JSON/tabular schemas from DATA_SCHEMA.md into strict Pydantic models (for API) and TypedDicts (for internal pipelines). Also provides boundary validators.
- **Files Owned:** `src/anomaly_detection/common/types.py`, `src/anomaly_detection/common/validators.py`.
- **Input:** DATA_SCHEMA.md specs.
- **Output:** Pydantic models (`RawAccessLog`, `AlertPayload`, etc.) and validation functions.
- **Acceptance Criteria:** All boundaries A-L schemas are represented as Pydantic models; instantiation with valid mock data passes; instantiation with invalid data raises `ValidationError`.
- **Dependencies:** M01.
- **Critical Path:** Yes

**M03: Synthetic Data Generator (Core & Profiles)**
- **Tier:** T1
- **Effort:** M (2-4hrs)
- **Source:** SYNTHETIC_DATA_GENERATOR_DESIGN.md
- **Scope:** Implements base entity profiles (User, Service Account, Edge Device), handles normal event generation (Poisson timing), and writes labeled ground truth. Also implements the Late Joiners 5% rule. Does not inject attacks.
- **Files Owned:** `src/anomaly_detection/data_generator/generator.py`, `src/anomaly_detection/data_generator/entity_profiles.py`, `src/anomaly_detection/data_generator/label_store.py`, `src/anomaly_detection/data_generator/schemas.py`.
- **Input:** Config parameters from `default.yaml`.
- **Output:** Normal access logs to `data/raw/` and labels to `data/labeled/`.
- **Acceptance Criteria:** Generator produces a 30-day timeline for 500+ entities with normal noise. Exactly 5% of entities have zero events before Day 26.
- **Dependencies:** M01, M02.
- **Critical Path:** Yes

**M04: Synthetic Data Generator (Attack Injection)**
- **Tier:** T1
- **Effort:** L (4-8hrs)
- **Source:** ATTACK_TAXONOMY.md, SYNTHETIC_DATA_GENERATOR_DESIGN.md
- **Scope:** Implements the 7 attack type simulation algorithms (including Insider Drift and Low-and-Slow) and interleaves them into the normal timeline generated by M03.
- **Files Owned:** `src/anomaly_detection/data_generator/attack_injector.py`, `scripts/generate_data.py`.
- **Input:** Base event timelines from M03.
- **Output:** Final anomalous access logs to `data/raw/`.
- **Acceptance Criteria:** `generate_data.py` executes successfully. Generated logs exhibit the specific statistical markers (e.g. `geo_velocity_kmph` > 1000 for Impossible Travel) defined in ATTACK_TAXONOMY.md for ~1.5% of events.
- **Dependencies:** M03.
- **Critical Path:** Yes

### Wave 2 (ML Data & Stores)

**M05: Entity Profile & Alert Stores**
- **Tier:** T1
- **Effort:** S (<2hrs)
- **Source:** ARCHITECTURE.md, PROJECT_STRUCTURE.md
- **Scope:** Implements the SQLite backend for the Profile Store (Boundary E) and the Alert & Result Store (Boundary J). Handles reads, upserts, and schema initialization.
- **Files Owned:** `src/anomaly_detection/stores/profile_store.py`, `src/anomaly_detection/stores/alert_store.py`, `src/anomaly_detection/stores/backends/in_memory.py`, `src/anomaly_detection/stores/backends/sqlite.py`.
- **Input:** M02 data models.
- **Output:** Read/write interfaces for profiles and alerts.
- **Acceptance Criteria:** Stores initialize SQLite DBs in `data/`; successful CRUD operations using Pydantic models.
- **Dependencies:** M02.
- **Critical Path:** Yes

**M06: Feature Engineering Pipeline**
- **Tier:** T1
- **Effort:** M (2-4hrs)
- **Source:** DATA_SCHEMA.md
- **Scope:** Constructs the 24-dimensional feature vector, computes rolling stats, handles categorical encoding, and maintains the 20-event sliding window. 
- **Files Owned:** `src/anomaly_detection/feature_engineering/session_builder.py`, `src/anomaly_detection/feature_engineering/sequence_builder.py`, `src/anomaly_detection/feature_engineering/encoders.py`, `src/anomaly_detection/feature_engineering/geo_velocity.py`.
- **Input:** Boundary B events, current `EntityProfile` from M05.
- **Output:** Boundaries C (EngineeredFeatures, sequence tensor).
- **Acceptance Criteria:** Given a RawAccessLog, outputs a length-24 numpy array and a (1, 20, 24) tensor matching schema specs.
- **Dependencies:** M02, M05.
- **Critical Path:** Yes

### Wave 3 (ML Core)

**M07: Behavioral Profiling Model (BPM)**
- **Tier:** T1
- **Effort:** M (2-4hrs)
- **Source:** ML_PIPELINE.md (Sec 2)
- **Scope:** Implements the per-entity Isolation Forest, Z-Score fallback, and normalization. Includes trainer and inference logic.
- **Files Owned:** `src/anomaly_detection/models/behavioral_profiling/base.py`, `src/anomaly_detection/models/behavioral_profiling/trainer.py`, `src/anomaly_detection/models/behavioral_profiling/inference.py`.
- **Input:** Boundary C feature vectors.
- **Output:** BPM ModelScore (Boundary F).
- **Acceptance Criteria:** Model trains on normal data, serializes to disk, and assigns an anomaly score [0,1] to new vectors.
- **Dependencies:** M06.
- **Critical Path:** Yes

**M08: Sequence Detection Model (SDM)**
- **Tier:** T1
- **Effort:** L (4-8hrs)
- **Source:** ML_PIPELINE.md (Sec 3)
- **Scope:** Implements the per-entity-type PyTorch GRU Autoencoder and masked reconstruction loss. Includes trainer and inference logic.
- **Files Owned:** `src/anomaly_detection/models/sequence_detection/base.py`, `src/anomaly_detection/models/sequence_detection/trainer.py`, `src/anomaly_detection/models/sequence_detection/inference.py`.
- **Input:** Boundary C sequence tensors (1, 20, 24).
- **Output:** SDM ModelScore (Boundary F).
- **Acceptance Criteria:** Model trains without crashing, loss decreases, handles padding masks correctly, outputs normalized anomaly score [0,1].
- **Dependencies:** M06.
- **Critical Path:** Yes

**M09: Score Fusion & Classifier**
- **Tier:** T1
- **Effort:** M (2-4hrs)
- **Source:** ML_PIPELINE.md (Sec 4 & 5)
- **Scope:** Implements score fusion (weighted avg) and the LightGBM Anomaly Classifier with SMOTE and class weights.
- **Files Owned:** `src/anomaly_detection/models/fusion/score_fusion.py`, `src/anomaly_detection/classifier/base.py`, `src/anomaly_detection/classifier/trainer.py`, `src/anomaly_detection/classifier/inference.py`.
- **Input:** Boundary F scores, Boundary C full vector.
- **Output:** ClassificationResult (Boundary H).
- **Acceptance Criteria:** Classifier trains on 27-dim vectors, handles extreme imbalance via SMOTE/weights, and overrides prediction to "normal" if fused score is below threshold.
- **Dependencies:** M07, M08.
- **Critical Path:** Yes

## 2. Build Sequence & Concurrency

| Wave | Modules | Concurrency Rules |
|------|---------|------------------|
| **1: Foundation** | M01, M02, M03, M04 | **Sequential:** M01 -> M02 -> M03 -> M04. Data schemas (M02) are required before generator (M03) can output them. |
| **2: ML Stores** | M05, M06 | **Parallelizable:** Store DB setup (M05) and Feature Engineering (M06) can happen in parallel, but both depend on M02. |
| **3: ML Core** | M07, M08, M09 | **Semi-Parallel:** BPM (M07) and SDM (M08) can be built in parallel. Classifier (M09) strictly awaits M07 and M08 completion. |
| **4: Intel** | M10, M11 | **Sequential:** Explainability (M10) feeds into the final Orchestrator update steps (M11). |
| **5: Backend** | M12, M13 | **Sequential:** Core FastAPI + Inference (M12) must be done before SSE Streaming (M13). |
| **6: UX & Eval** | M14, M15 | **Parallelizable:** Frontend (M14) and Offline Evaluation (M15) can be built in parallel. |

## 5. Time-Pressure Cut Protocol

If execution runs short on time, features will be dropped in this exact order to preserve a working Tier 1 presentation:

1. **First Cut (Tier 3 luxuries):** Dashboard visual charting (`visualizations.js`), MITRE ATT&CK mappings, and Analyst Feedback endpoints.
2. **Second Cut (Tier 2 evaluation & handlers):** Automated evaluation harness (`run_evaluation.py`) and specific drift recalibration loops. We will rely on manual demo verification and hardcoded drift freezing.
3. **Third Cut (Tier 1 Explainability depth):** Fallback from Captum Integrated Gradients (expensive/complex) to simpler ablation or pure feature weight mappings if PyTorch SHAP proves too slow to implement under deadline.
4. **Final Defense Line:** Must preserve the End-to-End Pipeline (FastAPI -> BPM/SDM -> Alert SQLite -> Dashboard UI) using mock generator data.
