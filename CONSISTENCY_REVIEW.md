## 2. Schema Consistency Audit

Verified field names, types, and constraints across boundary contracts.

**Issues Found:**
1. **`SessionMetadata.is_cold_start` vs `EntityProfile.cold_start_flag`:** 
   - *Location:* `DATA_SCHEMA.md` uses both names in different objects. `API_SPEC.md` uses `is_cold_start` for the entity status response. 
   - *Resolution:* Non-blocking. Semantic overlap is clear, but `cold_start_flag` should be canonicalized across all objects during implementation to avoid parsing errors.
2. **`RiskScore` Object Reference:**
   - *Location:* The prompt for Phase 9 requested a `RiskScore` object, but `DATA_SCHEMA.md` correctly defines it as an `int`. `API_SPEC.md` correctly handled this by using the primitive `int`. 
   - *Resolution:* Consistent in documents. No action required.
3. **Feature Attribution Source Model:**
   - *Location:* `DATA_SCHEMA.md` limits `source_model` to `"bpm"` or `"sdm"`. `ML_PIPELINE.md` specifies a deduplicated union of features. 
   - *Resolution:* Non-blocking. If a feature is highlighted by both models, the explainability module must either output two `FeatureAttribution` entries or pick the one with the higher magnitude. The schema supports this natively.

## 3. Interface Compatibility Audit

Verified that outputs from producing components exactly match inputs for consuming components.

**Issues Found:**
1. **Profile Updater Placement:**
   - *Location:* `COLDSTART_DRIFT_STRATEGY.md` states the EWMA baseline update is gated by `fused_score < 0.4`. `fused_score` is generated at Boundary G (Score Fusion). 
   - *Issue:* `ML_PIPELINE.md` does not explicitly define an "Update Profile" step that consumes Boundary G and writes to the Profile Store. 
   - *Resolution:* Blocking. The Orchestrator (FastAPI background task) must explicitly pass the `feature_vector` and the `fused_score` to the `ProfileStore.upsert()` method after inference finishes, to execute the Gated EWMA.

   - *Location:* `DASHBOARD_UX.md` specifies a paginated table. `API_SPEC.md` and `DATA_SCHEMA.md` include `total_count` in `RenderedAlertData`.
   - *Resolution:* Consistent.

## 7. Evaluation Compatibility Audit

Verified that `EVAL_METRICS.md` protocols are executable given the data generated by `SYNTHETIC_DATA_GENERATOR_DESIGN.md`.

**Issues Found:**
1. **Cold-Start Entities in Test Set:**
   - *Location:* `EVAL_METRICS.md` flagged that the Poisson distribution in `SYNTHETIC_DATA_GENERATOR_DESIGN.md` cannot generate entities with 0 events in the training split. 
   - *Issue:* `SYNTHETIC_DATA_GENERATOR_DESIGN.md` was never explicitly patched with the "Late Joiners" requirement proposed in Phase 8. If implemented as currently written, the cold-start evaluation script will fail because there will be no cold-start entities in the test split.
   - *Resolution:* Blocking. `SYNTHETIC_DATA_GENERATOR_DESIGN.md` must be updated to force 5% of generated entities to start their event streams on Day 26.

## 10. Required Document Corrections

To resolve the blocking issues, the following specific corrections must be applied to the design documents before Phase 13 begins:

**Correction 1: Update `SYNTHETIC_DATA_GENERATOR_DESIGN.md`**
- *Action:* Add a new sub-section under Section 2 (Entity Profiles) titled "2f. Cold-Start Holdout Group (Late Joiners)".
- *Content to Insert:* "To satisfy the evaluation protocols, exactly 5% of all generated entities must be designated as 'Late Joiners'. For these entities, the generator must enforce that no events are emitted between Days 1–21. Their Poisson sampling timeline must be restricted exclusively to Days 26–30, ensuring they trigger the cold-start fallback logic during testing."

**Correction 2: Update `ML_PIPELINE.md`**
- *Action:* Add a step to Section 2 (The Inference Pipeline Orchestrator).
- *Content to Insert:* "Step 5b (Profile Updating): After Boundary G (Score Fusion) is computed, the orchestrator must pass the `feature_vector` and `fused_score` to the Profile Store. The Profile Store will execute the Gated EWMA Concept Drift logic (freezing if `fused_score >= 0.4`, updating otherwise) before the Alert Payload is persisted."

## 11. Cleared-for-Implementation Statement

**Status: NOT CLEARED FOR IMPLEMENTATION.**

There are two blocking issues (The Late Joiner generation logic and the Profile Update orchestrator step) that present concrete failure points for evaluation and concept drift handling. 

Once the corrections detailed in Section 10 are applied to `SYNTHETIC_DATA_GENERATOR_DESIGN.md` and `ML_PIPELINE.md`, the architecture will be fully reconciled and cleared for Phase 13 (Implementation).
